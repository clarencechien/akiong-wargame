# PRD：如果你是阿共，你要怎麼打過來

2026-10-02 · Clarence · 草稿 v0.2

## 產品定位與教育目標

一個單人台海兵推模擬器：玩家坐在解放軍聯合作戰指揮中心總指揮的位子上，設定一組開局假設，系統模擬一段「可能的歷史」，最後寫成一章未來教科書。目標是讓一般人親身撞到「中國要打台灣有多困難」這堵牆，而不是被告知。

**為什麼是攻方。** 困難只有從攻方位子才感受得到：想四月出兵就撞到天候窗口，想偷襲就撞到船團集結可見性，想持久就撞到家前線。守方視角只能看到結果，攻方視角才會看到限制。

**三個設計原則。**

1. 教育優先，但學理上要站得住：每個參數附公開來源，可點開檢視；超出公開資料範圍的數字強制標紅。
2. 不追求聲光，追求「有感」：戰場數字與各階層人物的聲音交錯出現，讓宏觀決策的代價落到具體的人身上。
3. 每一局都是一段平行歷史：同一組假設跑 100 次會得到分佈，玩家看到的不是「結果」而是「機率」。

## 目標使用者與「會有人想玩」的機制

主要使用者是對台海議題有興趣、沒有軍事背景的一般人；其次是老師、講者與社群創作者，拿它當教材或內容素材；最後是原本就玩兵推的人，會來挑戰參數邊界。

**吸引人的不是聲光，是三個鉤子。**

| 鉤子 | 玩家體驗 | 對應功能 |
| --- | --- | --- |
| 「我來試試」 | 標題就是挑戰：如果你是阿共，你要怎麼打過來 | 攻方視角、八個假設 |
| 「原來是這樣」 | 每個假設旁的情報評估隨選擇即時改變，撞牆發生在下令之前 | 作戰室的情報評估列 |
| 「我要給別人看」 | 一局結束得到一章教科書、一張頭版卡、一支 45 秒短影音 | 史書的三種輸出 |

重玩的動力來自「如果重來」：改一個假設再跑，看哪個變數真的改變結局、哪個只改變代價。同組假設跑 100 場的分佈，讓玩家知道自己這一局是常態還是極端。

## 理論基礎與資料來源

模型站在四根柱子上，每根各管一層。所有參數都在 UI 上附來源標籤，點開可看出處與簡化方式。

| 來源 | 管哪一層 | 拿什麼 |
| --- | --- | --- |
| CSIS《The First Battle of the Next War》(2023) | 軍事層的骨架 | 五階段結構、美日介入情境、船團損耗量級、24 次兵推的結果分佈 |
| 《阿共打來怎麼辦》《再談阿共打來怎麼辦》 | 常識層的約束 | 天候窗口、灑頭數量、動員可見性、飛彈數量與實際效果、常見誤解 |
| Easton《The Chinese Invasion Threat》(2017) | 地理層 | 西岸 14 處可登陸灑頭、東岸地形限制、澎湖的角色 |
| DoD《中國軍力報告》、各國公開數據 | 數字層 | 艦艇與滿裝船數量、飛彈庫存、底線經濟數據（台商在陸就業、晶片依存度） |

**精確度原則。** 教育優先，但學理與邏輯上要站得住：

1. 數字用區間不用點估計，模擬時在區間內抽樣；來源不足的參數標註「模型假設」。
2. 第一版先把每個參數的公開範圍標出來，超出範圍的設定標紅，史書與事件簿同步高亮；資料來源頁另闢「現實面的考量」一節，寫明這份教材不周全之處與未來可能怎麼補。
3. 簡化要說明：空戰不分高層、飛彈軌跡用直線、電戰只用一個衰減係數。這些簡化寫在資料來源頁，不藏。
4. 結論要和公開兵推的量級一致：同組假設的分佈要落在 CSIS 結果的合理範圍內，否則視為模型錯誤。

**來源頁的致謝與限制。** 資料來源頁明文致敬《阿共打來怎麼辦》兩位作者與軍事科普的目標，同頁放「現實面的考量」：哪些簡化是刻意的、哪些是資料不足、未來可能怎麼做。這一頁是教材的一部分，不是免責聲明。

## 核心循環與三個畫面

一局是「作戰室 → 戰情室 → 史書 → 如果重來」的循環，全程在本機完成。視覺上作戰室與史書是紙本檔案，戰情室是房間裡那塊暗色螢幕；兩者刻意不同。

| 畫面 | 玩家做什麼 | 畫面上有什麼 |
| --- | --- | --- |
| 01 作戰室 | 設八個假設、選場數、下令 | 身分卡、攻擊軸小地圖（隨⑦⑧改變）、八個假設與即時情報評估、開局前評估 |
| 02 戰情室 | 看（第一版不下指令）：播放、拖時間軸、切層 | 五階段進度條、台海地圖（真實輪廓、西岸東岸灑頭、澎湖、琉球、美日兵力）、四層態勢儀表、下一道門檻、聲音流 |
| 03 史書 | 讀、分享、重來 | 教科書章節、頭版分享卡、分階段短影音、事件簿、本局在 100 場中的位置、如果重來 |

Mockup 在 Design 畫布上，第二排為 v2。戰情室的地圖不追求精細：真實輪廓、网格、符號，到此為止；精細地圖會讓人誤以為這是軍事模擬器。

## 假設層：八個開局假設

第一版玩家不下即時指令，「決定」全部前移到開局假設。每個假設都對應一個常見誤解，選項旁的情報評估就是教材。八個假設的組合數約 25,000 種，全部即時在本機運算，不預算。

| # | 假設 | 選項 | 模型裡影響什麼 | 教的誤解 |
| --- | --- | --- | --- | --- |
| ① | 發動月份 | 1–12 月 | 可用海況窗口天數、渡海損耗係數 | 「想打就打」：其實只有四月與十月兩個窗口 |
| ② | 動員規模 | 偷襲型／中型／全面＋徵用民船 | 集結週數、被發現日、第一波運量 | 「可以突襲」：規模與驚喜不能兼得 |
| ③ | 美國介入 | 不介入／延遲 D+7／立即 | 美軍打擊起始日、對船團的額外損耗 | 「美軍不來就打得下」：不介入線也不到五成 |
| ④ | 日本態度 | 中立／開放基地／參戰 | 美軍出擊架次係數、琉球封鎖線 | 「日本只是旁觀者」：沒有沖繩基地介入形式完全不同 |
| ⑤ | 台灣後備動員率 | 30%／55%／80% | 灑頭後方縱深撐幾天 | 「登陸就結束了」：登陸只是開始 |
| ⑥ | 經濟自損容忍 | 低（30 天內收尾）／高（不計代價） | 持久上限、家前線事件觸發日 | 「中國可以打持久戰」：持久的代價先落在自己人身上 |
| ⑦ | 主攻軸 | 北部／中部／南部／東岸（標紅） | 可用灑頭數、守備旅數、距政經中心距離、是否可補給 | 「從東部繞後」：東岸可登陸但背靠中央山脈，不可補給 |
| ⑧ | 輔助作戰 | 無／先取澎湖／東岸佯攻／封鎖為主 | 從同一池運量扣除；澎湖 -18%、東岸佯攻 -12% 但可能拖住守方 1 旅 | 「兩面作戰」：運量是固定的，多一個方向就少一块 |

⑦⑧是回答「有沒有東岸登陸與兩面作戰」的方式：模型允許，且讓玩家自己發現為什麼公開分析都把東岸當佯攻而非主攻。封鎖為主是 Run 2 才解鎖的選項，不在第一局（見模擬引擎的 Run 2）。

## 模擬引擎：五階段門檻、地理、美日介入

引擎是固定時間步長（1 小時一個 tick）的決定性模擬：同一組假設加同一個 seed，結果永遠相同。每個 tick 推進四層狀態量，並檢查當前階段的門檻。

> 圖：模擬引擎五階段與門檻（見 `docs/engine-phases.png`）。每階段一道門檻，過不了就提前結算 → 史書。

每一道門檻都是公開資料裡的硬約束，不是遊戲平衡數字；大多數局在渡海或搶灘就結束，這和公開兵推的分佈一致。

**地理：西岸、東岸、澎湖。**

| 區域 | 灘頭 | 守備 | 模型處理 |
| --- | --- | --- | --- |
| 西岸北部（林口、竹北） | 多，近政經中心 | 最厚 | 預設主攻軸 |
| 西岸中部（台中港） | 中 | 中 | 可選主攻軸 |
| 西岸南部（枋寮、高雄外圍） | 中 | 中 | 可選主攻軸 |
| 東岸（花蓮、台東） | 3 處，狹窄 | 薄 | 可登陸、不可補給；往西要翻中央山脈，模型以「無法連通西部」處理，選為主攻標紅 |
| 澎湖 | 獨立島群 | 1 旅 | 先取可當跳板，但扣 18% 運量並多給守方 2 天 |

**美日介入。** 美軍介入日由假設③決定，介入後對渡海船團與灘頭補給線加一層損耗；日本態度決定介入的形式（關島與航母 vs 沖繩與九州基地）與出擊架次係數。第一版不模擬美軍自身損失與中美升級，只模擬對登陸的影響。

**Run 2：封鎖。** 第一局登陸撞牆後玩家一定不服氣，第二局開放封鎖層面的選項：宣布封鎖區、臨檢與扣船、切斷能源航線、對突破護航開火。封鎖是開戰，不是灰色作戰；它在軍事層幾乎沒有門檻，真正有感的是世界層：台灣能源天數、航運改道與保費、中國自身出口受阻、各國反應。引擎為此多一條以「消耗」而非「門檻」推進的階段梯（宣布 → 執行與臨檢 → 突破嘗試 → 國際反應 → 消耗戰），四層架構與聲音系統不變，人物庫加航運與港口的人。

## 四個影響層的狀態量

四層在每個 tick 同步推進，軍事層是駅動層，其他三層由軍事事件與時間觸發，再回頭影響軍事層（家前線壓力會壓低持久上限）。第一版每層只維持少數幾個狀態量，全部顯示在戰情室左欄。

| 層 | 狀態量（第一版） | 誰改變它 | 它影響誰 |
| --- | --- | --- | --- |
| 軍事 | 船團存活率、海峽制空、守方岸置飛彈剩餘、上岸兵力、補給線存活天數 | 階段邏輯、天候、美日介入 | 門檻判定、所有層的觸發 |
| 區域 | 美軍介入倒數、日本基地狀態、琉球封鎖線、韓國菲律賓態度 | 假設③④、時間 | 軍事層損耗係數 |
| 世界 | 晶片產能、海運保費與航線、能源價格、市場指數 | 封鎖與打擊事件 | 聲音系統、史書的世界段落 |
| 家前線 | 沿海就業（停工比例）、台商薪資依存度、士氣、物價 | 時間、經濟自損容忍、世界層 | 持久上限、聲音系統的觸發密度 |

家前線層是這個產品與其他兵推最大的差別，第一版就做。它的起點是一個公開可查的數字：在陸台商雇用的勞工數，與戰時資金無法匯入的後果。

## 聲音系統：各階層人物的隨機事件

聲音是一種事件，和軍事事件在同一條流裡交錯出現。家書只是其中一種；人物庫要跨階層、跨地域、跨立場，讓玩家聽到的是一個社會，不是一個受害者。

**人物庫（第一版約 30 人）。**

| 階層 | 人物例 | 觸發條件 | 聲音的味道 |
| --- | --- | --- | --- |
| 前線 | 集團軍列兵、船團輪機長、飛行員 | 軍事事件、家前線事件（家書） | 短、具體、不談大局 |
| 家前線勞工 | 東莦線長、泉州漁民、徵用民船船東 | 停工比例、徵用事件 | 算帳、問「那我怎麼辦」 |
| 台商 | 昆山二代、東莦老闆、在陸台幹 | 資金無法匯入、停工 | 夾在中間，兩邊都不是自己人 |
| 體制內 | 市委書記、官媒編輯、徑警 | 家前線壓力超過門檻 | 內部通報語氣，字裡行間有事 |
| 後方家庭 | 上海母親、河南老父、大學生 | 士氣下降、資訊封鎖 | 新聞說一切順利，但兒子沒回訊息 |
| 區域 | 石垣島民宿老闆、釜山貨櫃場調度、馬尼拉漁工 | 區域層事件 | 戰爭不在我家，但已經在我家 |
| 世界 | 紐約半導體分析師、新加坡航運經理、慕尼黑車廠採購 | 世界層事件 | 模型算不出來、供應鏈斷裂 |
| 台灣 | 台東漁民、林口後備軍人、竹科工程師 | 軍事事件、停工 | 守方視角只在聲音裡出現，不在操作裡 |

**模板與 seed 的分工。** 開發期用 LLM 批次產生每個人物的多條語句模板（含變數槽：天數、部隊番號、金額、地名），人工審過後存成靜態 JSON 隨程式出貨。執行期不呼叫任何 API：觸發時以 seed 從人物庫抽人、從該人的模板抽句、填入當前狀態量。同一 seed 永遠得到同一句，分享時才能重現。

1. 觸發規則寫在模板上：哪一層、哪個狀態量、超過什麼門檻、哪個階段。
2. 同一人物在一局中最多出現三次，且語氣要隨狀態變化（先算帳、後麻木）。
3. 每句聲音都能點回觸發它的事件與數據，史書裡引用時附上來源編號。
4. 不寫具名真實人物，不寫血腥細節；聲音的力量來自平常。

## 史書輸出：章節、頭版分享卡、分階段短影音

同一份事件流，四種讀法；第一版全部在本機產生，以檔案下載。每種輸出都帶着 seed 與假設編碼，第二版才能靠它重現。

| 輸出 | 形式 | 給誰 | 第一版做法 |
| --- | --- | --- | --- |
| 教科書章節 | 1,500–3,000 字，三到四節，引述聲音，註釋回溯數據 | 想讀完整故事的人 | 模板拼裝，段落由階段與結束原因決定 |
| 頭版分享卡 | 1080×1350 PNG：一句標題＋假設摘要＋分佈小圖＋ seed | 社群轉發 | Canvas 繪製後下載；標題由「玩家原本押的變數」與「實際終止原因」組成 |
| 分階段短影音 | 直式 9:16，每階段一幕約 8 秒，全長約 45 秒；每幕＝地圖動態＋一個數字＋一句聲音 | 短影音平台 | 初期用 HTML motion（hyperframe 風格）在瀏覽器播放與錄製，作為擴散用；同時給一份 template 與素材包（地圖、數字卡、聲音卡），想二創的人自己加工；背景音樂 1.x 加入 |
| 事件簿 | 逐行事件與狀態量，超出公開資料的設定高亮 | 想查證的人、老師 | JSON / CSV 下載 |

頭版卡是傳播的主力：一張圖說完「我以為問題是美軍，問題是船不夠、天不夠、錢不夠」。短影音模組可延後到 1.1，不阻擋 MVP。

章節的書名與章號每局隨機，從一組史書風書名庫抽（《東亞現代史 · 下冊》《海峽百年》《第二次太平洋戰爭史》之類），章號與年代跟著假設與結局變，強化平行歷史感。

## 技術架構

第一版是一個靜態網站：所有運算在玩家的瀏覽器，不上傳任何資料，沒有帳號。這直接避開原作者撞到的伺服器運算牆。

| 層 | 第一版 | 第二版加上 |
| --- | --- | --- |
| 引擎 | TypeScript，跑在 Web Worker；決定性、固定步長、seed 可重現；單場目標 < 1 秒，100 場用全部核心平行 | 熱點改 Rust → WASM |
| 資料 | 靜態 JSON：參數庫（含來源與區間）、人物庫、語句模板、章節模板 | 同 |
| 前端 | 單頁應用，三個畫面；地圖為 SVG；分享卡 Canvas；短影音 WebCodecs | 同 |
| 儲存 | 本機 IndexedDB：已跑過的局（假設編碼＋seed＋結果摘要） | Cloudflare D1 收假設編碼＋seed＋結果摘要；不收事件簿 |
| 分享 | 下載 PNG / MP4 / JSON | 分享連結 = 假設編碼＋seed，打開連結在對方瀏覽器重算；Worker + R2 生成預覽圖 |
| 共享統計 | 無 | 同組假設的全站分佈（「1,284 人跑過」），只聚合不存個人 |
| 主機 | 靜態檔案，Cloudflare Pages 或任何靜態空間 | Workers + D1 + R2 |

分享連結只帶 seed 而不帶結果，是因為引擎決定性：對方打開連結時在自己電腦重算同一局，伺服器永遠不跑模擬。引擎版本號要進分享編碼，舊版局才重現得出來。

## 版本規劃與 MVP 不做的事

| 版本 | 目標 | 內容 |
| --- | --- | --- |
| 1.0 MVP | 教育，且有人想玩 | 單人、全本機；八個假設；五階段引擎；四層狀態量；30 人人物庫；章節＋頭版卡＋事件簿；100 場分佈；資料來源頁 |
| 1.1 | 傳播 | 短影音 template 與素材包、背景音樂；人物庫擴到 120 人，以人物 × 處境 × 語氣的組合抽樣增加隨機感；Run 2 封鎖選項 |
| 2.0 | 分享與共享統計 | Cloudflare 收 seed；分享連結重算；同組假設的全站分佈 |
| 3.0 | 下決定 | 階段門檻處的決策點（繼續、轉封鎖、停止）；平行宇宙分岔 |
| 後續 | 多人與即時 | Durable Objects，紅藍對打，伺服器端戰爭迷霧 |

**MVP 明確不做。**

- 即時指令、多人、帳號、任何上傳
- 空戰分層、單一武器參數調校、電戰細部模型
- 精細地圖、單位級的符號與動畫
- 守方視角的操作（守方只在聲音裡出現）
- 执行期呼叫 LLM（模板在開發期生成、人工審過）
- 中美升級、核選項、美軍自身損失

## 風險與未決問題

| 風險 | 影響 | 對策 |
| --- | --- | --- |
| 模型被認為「答案先行」，只是包裝成模擬 | 教育可信度歸零 | 每個參數附來源與區間；分佈要對得上 CSIS；事件簿全部可下載；允許玩家把參數拉到標紅區自己試 |
| 攻方視角被誤讀為立場 | 傳播時被攻擊 | 標題與開局文案說清楚為什麼是攻方；聲音系統讓兩岸社會都有人的臉 |
| 聲音模板寫得像 AI | 有感變無感 | 人工審稿每一句；寬量生成、嚴格篰選；語氣要有地域與階層差 |
| 對方裝置跑 100 場太慢 | 分佈功能沒人用 | 預設 10 場；手機上限制場數；引擎先做效能預算 |
| 兩本書與 CSIS 的數字互相矛盾 | 參數庫難定 | 矛盾處用區間涵蓋兩者，來源頁寫明兩種說法 |

**未決問題。**

已定：Run 2 封鎖放 1.1；背景音樂之後用 Suno 生成；「現實面的考量」那一頁先由 AI 生成初稿，再人工改。目前沒有未決問題。
