# ADR-0001：§5.2 驗收以「穩固灘頭堡」為準

- 狀態：已採納
- 日期：2026-10-02
- 決策者：Clarence（規格方）
- 關聯：`docs/HANDOFF.md` §5.2、`docs/model.md` §3–4、`tests/engine.distribution.test.ts`

## 背景

HANDOFF §5.2 原本寫：基準假設 1,000 場，「建立灘頭堡比例 10–30%、30 天內達成目標 < 10%、中位終止日 D+5 到 D+12」。M1 引擎以 CSIS 2023、Easton、DoD CMPR、中央氣象署的數字建模，不調平衡係數，量測結果：

| 指標 | 原字面 | 量測 |
| --- | --- | --- |
| 登陸成功（landing 門檻：存活 48 小時且第二波卸載） | 10–30% | 59.5% |
| 穩固灘頭堡（補給 ≥ 3 天且兵力 ≥ 所需） | — | 8.7% |
| 30 天內達成目標 | < 10% | 0.1% |
| 中位終止日 | D+5 到 D+12 | D+13 |

CSIS 24 局中解放軍每一局都上得了岸（基準局 37 個營、約 3 萬人），0 局中國勝、3 局僵局偏中國、其餘敗；輸在船團 10–14 天內被擊沉與灘頭斷補給。以公開資料建模，「上岸」不是最難的門檻，「上岸後活下來」才是。

## 兩個選項差在哪

1. **設定（主因）**：HANDOFF 的「建立灘頭堡」= landing 門檻；CSIS 判定用的是「穩固灘頭堡 + 控制足夠港口機場」。同一組事實換個名詞，數字從六成變一成。
2. **假想（次因）**：HANDOFF／PRD「多數局在渡海或搶灘就結束」是《阿共打來怎麼辦》的世界觀（海峽本身是牆）；CSIS 的世界觀是第一趟過得去、死在第二到第四趟。基準假設「美軍延遲 D+7」在 CSIS 沒有對應局，只有 D+0 介入與台灣單獨作戰兩個端點，模型是內插。
3. **資料不足（分不出高下的那塊）**：要讓原字面成立，需要「首波換乘衝灘就被打回海裡」的高機率。書裡講灘頭幾百公尺寬、火砲、水雷、障礙，但沒有數字；CSIS 用二戰末期美軍卸載率，沒給灘岸損失。目前 `beach.surfZoneLoss` = 10%（5–20%）是歷史類比，要拉到 40% 以上才會讓首波常態性失敗，公開資料裡沒有支持或反對它的數字。

## 決策

採選項 1：

- §5.2 改為「穩固灘頭堡 5–30%、登陸成功 ≥ 40% 且高於穩固灘頭堡、目標 < 10%、中位終止日 D+8 到 D+14」。
- `Run.outcome` 同時帶 `beachhead`（登陸成功）與 `solidBeachhead`（穩固灘頭堡）；戰情室、史書、分享卡都要同時顯示兩個數字，讓「上得了岸」與「活得下來」成為教材的一部分。
- 不採選項 2（維持原字面、加入首波被打回海裡的機制）。若日後要做，正確做法是把「首波灘岸損失」開成玩家可見、可調、超出 range 標紅的參數，並在來源頁寫明沒有公開依據；不是改隱藏係數。

## 後果

- M1 以新 §5.2 驗收通過，進 M2。
- 美軍延遲介入這一格沒有公開兵推對照，模型在這裡是內插；來源頁「現實面的考量」要寫。
- 《阿共打來怎麼辦》的「海峽是牆」論點在模型裡體現在月份（8 月登陸成功約 4%、12 月約 2%）、偷襲型規模（約 39%）與美軍立即介入（穩固灘頭堡 0.7%），而不是基準局的首波。
- 之後任何讓分佈漂出新區間的改動，都要回到 `docs/model.md` §4 的校準紀錄，補機制或修參數，不調係數。
